## 10. DAILY の実装方針（決定）

Instagram API 連携の案が出たが、**Shopify Blog で実装する**（仕様どおり）。

見送った理由:
- Shopify のテーマは Liquid と静的JSのみでサーバー処理を持てず、アクセストークンを安全に保持できない。
  このリポジトリは public のため特にリスクが高い
- Instagram Basic Display API は 2024年12月4日に提供終了。現行の
  Instagram API with Instagram Login はプロアカウント（ビジネス/クリエイター）が必須で、
  トークンの定期更新も必要。実現にはアプリ導入か自前プロキシが要る
- Instagram フィード化すると DAILY一覧・DAILY記事ページが無くなり、外部遷移になる

公開後に載せ替える場合は Shopify アプリ（Instafeed 等）が現実的。

参考: https://developers.facebook.com/blog/post/2024/09/04/update-on-instagram-basic-display-api/

商品名が1行の商品と2行の商品が並ぶと、価格とボタンの位置がずれていた
（PICKUP の TOTE BAG は2行、CAP は1行）。

## 13. カードの見栄え / ホバー演出

参考スクリーンショット（白カード・角丸・やわらかい影）に寄せた。
**Dawn のテーマ設定で実現できるものは設定で行い、CSSは補助に留めている。**

### テーマ設定（`config/settings_data.json`）
商品カード / コレクションカード / ブログカードの3系統に同じ値を適用。

| 設定 | 変更前 | 変更後 |
|---|---|---|
| `*_style` | standard | **card** |
| `*_color_scheme` | scheme-2 (#f3f3f3) | **scheme-1 (#ffffff)** |
| `*_corner_radius` | 0 | **12** |
| `*_shadow_opacity` | 0 | **10** |
| `*_shadow_blur` | 5 | **20** |
| `animations_hover_elements` | none | **vertical-lift** |

### CSS（`assets/hrh-overrides.css`）
`docs/実装仕様.md` 10「過剰なアニメーション」を避け、気づくかどうかの範囲に留めた。

- Dawn 既定のリフト量 `-0.75rem`(12px) は強いため **5px** に抑制
- ホバー時に影をわずかに深く
- 商品画像を `scale(1.04)` でゆっくり寄せる（枠は動かさない）
- ボタンの色変化にトランジション
- キーボード操作時の `:focus-visible` 表示

動きを伴う指定はすべて
`@media (prefers-reduced-motion: no-preference) and (hover: hover)` の中に置いた。
タッチ端末でホバー状態が貼り付くのを防ぎ、視差に弱い利用者の設定を尊重するため。

## 16. TOP の背景スライドショー

ブランドアートを画面いっぱいに固定し、その上のコンテンツ背景を不透明度95%の白にして、
うっすら透けて見える状態をつくった。

| ファイル | 内容 |
|---|---|
| `snippets/hrh-bg-slideshow.liquid` | 新規。背景レイヤーのマークアップ |
| `assets/hrh-bg-1〜5.jpg` | 新規。支給されたブランドアート5点 |
| `assets/hrh-overrides.css` | 背景レイヤーと透過のスタイル |
| `layout/theme.liquid` | `body` に `template-{{ template.name }}` を追加し、TOPでのみ描画 |

### 仕様
- 5枚を**10秒ずつ**巡回（1周50秒）。1枚あたり 2.5秒フェードイン → 5秒表示 → 2.5秒フェードアウト
- `position: fixed` で画面に固定。スクロールしても動かない
- `background-size: cover` のため画面比率によってはみ出す（意図どおり）
- JSは使わず CSS アニメーションのみ
- `prefers-reduced-motion: reduce` のときは切り替えを止め、1枚目だけを表示

### 透過の範囲
| 対象 | 扱い |
|---|---|
| 白いセクション（`#MainContent` 内の `.color-scheme-1`） | **95%** |
| 商品カード等（`.card--card`） | 不透明のまま（可読性のため） |
| ヘッダー | 不透明のまま（追従表示で下が透けると読みにくいため） |
| フッター（濃紺） | 不透明のまま |
| TOP以外のページ | 同じ背景を表示（全ページ適用に変更） |

### 画像の圧縮
支給画像は合計約4.0MB（2048x2048 が4点）あったため、
`sharp` で長辺1600px・JPEG品質72に縮小して **約1.2MB** にした。
背景は95%の白に隠れて5%しか見えないため、画質より表示速度を優先している。
`docs/実装仕様.md` 9.画像/パフォーマンス に沿う判断。

差し替える場合は `assets/hrh-bg-*.jpg` を同じ方針で圧縮してから置き換えること。
枚数を変える場合は `snippets/hrh-bg-slideshow.liquid` の配列と、
`hrh-overrides.css` のアニメーション周期（`50s`）・`@keyframes` の割合を合わせて調整する。

### 背景が見えないときの確認順
1. GitHub→Shopify の同期が完了しているか（数十秒〜数分かかる）
2. `body` に `template-index` クラスが付いているか（`layout/theme.liquid` で付与）
3. `body` の背景が透過しているか。`.gradient` は `background` ショートハンドで
   白を敷くため、`.template-index.gradient` の2クラス指定で打ち消している
4. 白の不透明度。初期は95%にしたが**5%しか透けず視認しづらかったため90%に変更**。
   さらに強めるなら `hrh-overrides.css` の
   `rgba(var(--color-background), 0.9)` の数値を下げる

背景レイヤーは当初 `z-index: -1` にしていたが、ルート背景との描画順で埋もれる余地があるため、
`.hrh-bg` を `z-index: 0`、コンテンツ側を `z-index: 1` とする正の重ね順に変更した。

## 17. 商品カードの余白とボタン

| 対象 | 変更 | 理由 |
|---|---|---|
| `spacing_grid_horizontal` / `spacing_grid_vertical` | 8 → **16** | カードが近すぎた。`docs/実装仕様.md` 8「カード間: 12〜16px」に合わせた |
| PICKUP / 新着 の `quick_add` | standard → **none** | カード全体がリンクのため「オプションを選択」ボタンは不要 |

商品一覧ページ（`templates/collection.json`）の `quick_add` は元から `none` のため、
これでサイト全体の商品カードの見え方が揃う。

`hrh-overrides.css` の商品名2行ぶんの `min-height` は引き続き有効で、
ボタンが無くなった後も価格の位置を揃える役割を果たす。

## 18. 検索機能の削除

依頼により検索機能を外した。

| ファイル / 設定 | 変更 |
|---|---|
| `sections/header.liquid` | `header-search` の描画を2箇所ともコメントアウト（虫眼鏡アイコンが消える） |
| `predictive_search_enabled` | true → **false**（予測検索のJSを読み込まない） |

`docs/固定仕様.md` は「検索はShopify標準でOK」としていたため、これは仕様からの変更。

補足:
- `/search` のURLとテンプレート（`templates/search.json`）は残している。
  Shopify が標準で持つURLで、消しても再生成されるため。導線が無いだけで実害はない
- Dawn 本体（`header.liquid`）への差分になるため、Dawn のバージョンアップ時は再適用が必要。
  該当箇所には `HONEY ROSIE HOUSE:` のコメントを入れてある
- 復活させる場合は上記2箇所のコメントアウトを戻し、`predictive_search_enabled` を true にする

### 全ページ適用に変更した経緯
当初は `template.name == 'index'` でTOPのみに限定し、`body` の `template-index` クラスで
CSSを絞っていたが、背景が表示されない事象が発生。

配信中の `hrh-overrides.css` をCDNから取得して検証したところ、CSS自体は正しく
配信・適用されていた（`.hrh-bg` も `@keyframes` も含まれていた）。
つまり原因はCSSではなく、`template.name` による条件分岐か `template-index` クラスの付与側。

切り分けのため**条件分岐そのものを廃止し、全ページで描画する方式に変更**した。
「全体に反映される形で」という当初の要望にも沿う。

### 純CSS実装への作り替え（切り分けの結論）

背景が表示されない件を次の順で切り分けた。

| 確認 | 方法 | 結果 |
|---|---|---|
| CSSが配信されているか | CDNから `hrh-overrides.css` を取得 | **OK**（`.hrh-bg` も `@keyframes` も含まれていた） |
| 最新版が届いているか | バージョン無しURLで再取得 | **OK**（`body.gradient` / `.85` を確認） |
| 画像が配信されているか | `hrh-bg-1〜5.jpg` をCDNで確認 | **OK**（全て HTTP 200） |
| テーマが合っているか | 利用者に確認 | **OK**（`theme-export-20260918`） |

残る変数は「Liquidスニペットが実際にDOMへ出ているか」だけだったため、
**Liquidを使わない純CSS実装に作り替えた。**

- `snippets/hrh-bg-slideshow.liquid` を削除
- `layout/theme.liquid` の `render` を削除
- 背景は `body::before` で描画し、`@keyframes` 内で `background-image` を差し替える
  （不透明度0の瞬間に切り替えるため、切り替わりは見えない）
- CSS内の相対パス `url("hrh-bg-1.jpg")` はテーマの `assets/` を指す

これでスニペットの描画有無・テンプレート判定に一切依存しなくなった。

### フェードの調整
当初はフェードを1秒・`linear` にしていたが、表示側が唐突に感じられたため
**2.5秒・`ease-in-out`** に変更した。出入りとも同じ長さ・同じイージングで動く。

白の不透明度は切り分けのため一時的に85%まで下げていたが、**95%に戻した**。
濃さを変えるのは `hrh-overrides.css` の
`rgba(var(--color-background), 0.95)` の数値ひとつ。

## 19. 商品ページの画像ギャラリー

カラーを切り替えないと他の画像が見えない状態だったため、
大きい画像の下にサムネイル一覧を出す一般的な商品ページの形にした。

| 設定（`templates/product.json`） | 変更前 | 変更後 | 意味 |
|---|---|---|---|
| `gallery_layout` | stacked | **thumbnail** | 大きい画像＋下にサムネイル一覧 |
| `mobile_thumbnails` | hide | **show** | スマホでもサムネイルを表示 |
| `hide_variants` | true | **false** | 選択中のカラー以外の画像も一覧に残す |

`hide_variants` が true だと、バリアントを選んだ時点でそのカラーの画像しか
表示されなくなる。これが「1枚しか出ない」原因だった。

サムネイルをタップすると大きい画像が切り替わる挙動は Dawn の標準機能。
拡大表示は `image_zoom: lightbox` のままで、大きい画像のタップで拡大できる。
